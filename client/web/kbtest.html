iPhone keyboard tests

Tap each button and see whether the iOS keyboard actually appears (a blinking caret alone is a fail). Then try the in-app variants on the live app.

Target fields

These are ordinary HTML inputs (font-size 16px, on screen).

1. Direct focus

Focus the field inside the event. If these fail, iOS is blocking more than Flutter.

Control: on Ali’s iPhone this did not open the keyboard.

2. Proxy then handoff

Focus a hidden 16px proxy in pointerdown, then move focus to the field after a delay. iOS should keep the keyboard if it opened.

3. Flutter-like interference

Reproduces what the Flutter engine does on a tap.

Control: a steal after focus dismisses the keyboard. This is what Flutter’s view-focus timer does.

Mirrors the new in-app default: if the steal already ran, touchend focus still works; if it would run after touchend, it is blocked.

In-app variants (after this page)

Sign in as usual, open a stream, then try New event and New stream. A green “kb=…” badge in the corner confirms which strategy is live.

/?kb=a — default: touchend + instant open + handoff, block view-focus steal
/?kb=b — old default: pointerdown + handoff (did not open the keyboard)
/?kb=c — touchend + handoff, without blocking the steal
/?kb=d — no proxy, just skip the open animation
